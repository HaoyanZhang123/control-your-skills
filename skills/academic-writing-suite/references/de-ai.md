# 去 AI 味

请求类型为「去 AI 味 / 降 AI / 自然化改写」时读本文件。目标不是口语化，是消除模板痕迹、保留文体应有的正式度。

改编自 [kipozannaki/Reduce-AI-Text](https://github.com/kipozannaki/Reduce-AI-Text)（MIT）；已剔除其工作区正反例库机制，只保留可直接执行的规则。

## 1. 改写前先判三件事

| 判什么 | 影响着什么 |
|---|---|
| **文体** | 学术、报告、技术文档的"自然"与小说、文案的"自然"不是一回事 |
| **正式度** | 学术/公文不得降级为口语；文案可适度口语化 |
| **结构约束** | 公式、编号、代码块、表格、分行必须原样保留 |

判不出且影响结果时问一次；不影响时按学术体默认推进并声明。

## 2. 四条学术专有禁令

### 2.1 反价值声明

**先下判断再举例**是 AI 最稳定的特征之一。

| 反例 | 改法 |
|---|---|
| `颜色信息是区分病害类型的重要线索` | 直接写颜色特征表现成什么样：`病斑在 HSV 空间的 H 分量分布与健康叶片重叠率低于 12%` |
| `纹理对于病害的精细分类具有重要价值` | 写出纹理具体起了什么作用，或删掉这句话 |
| `这项工作意义重大` | 删掉，让数据说话 |

判据：这句话有没有先给一个**评价**，再给**事实**。有就改。

### 2.2 反元评论

对"作者正在写什么"的评论，而不是内容本身。

禁止：`值得注意的是`、`需要指出的是`、`在某种程度上`、`从某种意义上说`、`不难看出`、`毋庸置疑`、`众所周知`、`It is worth noting that`、`Interestingly`（除非真的需要读者注意）。

处置：删除，直接陈述原本要说的事。

### 2.3 反总括—分述模板

先用一句话概括"将从几个方面分析"，再一条条列出来。

禁止：`从 X 角度分析，主要体现在以下 N 个维度`、`下面从三个方面展开`、`具体体现在以下几个方面`。

处置：删掉总括句，直接进入内容。分述结构本身可以留，但不要先宣告它。

### 2.4 反堆砌

- 每段末尾的「此外，X 也可用于 Y」式补充——删掉。
- 为形式整齐而让并列段落高度一致——让段落长短、详略、句式节奏有自然变化。
- 三段式排比（为修辞凑三项）——删到实际数目。
- 机械连接词（`首先……其次……再次……`）连续出现——改为靠逻辑关系衔接。

**注意**：学术写作允许保留 `一方面……另一方面`、`首先……其次`、`总体而言` 这类传统衔接词，但**不得过度堆砌**（连续三句以上）。

## 3. 学术文体下不许动的东西

去 AI 味 ≠ 删信息。下列内容一律保留：

- **术语、数据、引用标记、公式、单位、精度**——一个都不改。
- **防止过强主张的边界句与限定词**——`在……条件下`、`不能排除`、`受限于样本量`。删掉它们不会让文字更自然，只会让主张变强，那是另一种错误。
- **LaTeX 公式与环境、表格结构、代码块、编号体系**。
- **必要的重复**：同一个术语在全文重复出现是对的，不要为了"行文变化"换同义词。

## 4. 语体尺度

| 文体 | 尺度 |
|---|---|
| 学术论文 / 学位论文 / 期刊论文 | 保持学术书面语；删填充与价值声明；**不得口语化** |
| 技术文档 / 说明书 | 步骤、编号、警告、参数、代码原样保留；只删填充词 |
| 报告 / 总结 / 商业分析 | 事实与数据先行；删套话；不得把专业判断改成口语 |
| 公文 / 通知 / 政策文本 | 保持庄重规范；保留政策术语与固定表述；不动条款 |

**统一底线**：不出现「说白了」「得先」「搞定了」「拿捏」这类表达；不滥用「的、了、吧、嘛、呗」；不把「读取数据」改成「把数据读出来」。

## 5. 修改阈值

**宁缺毋滥。**

如果输入文本已经自然、地道、没有明显模板特征，**保留原文**并明确写：

```text
[检测通过] 原文表达自然，无明显 AI 痕迹，建议保留。
```

不要为了修改而修改。改为而改的代价：把作者原本准确的措辞换成了另一个 AI 的措辞。

## 6. 改写后自检

- [ ] 原意是否保留；有没有引入原文没有的事实。
- [ ] 数据、引用、公式、步骤是否完整，数字有没有动。
- [ ] 文体是否一致；有没有把学术降级成口语。
- [ ] 边界句是否全部保留。
- [ ] 是否无故新增列表或标题。
- [ ] 字数是否明显减少——明显减少要回头查是否误删了实质内容。
- [ ] 机械门禁（SKILL.md §5）是否跑过并记录了命中数。

## 7. 交付格式

改造稿 + 改动摘要（3–5 条，说明改了哪几类模板痕迹、保留了什么结构）。

**不输出「AI 味评分」或「AI 率」**——那既不可验证，也会诱导把改写目标变成"骗过检测器"而不是"写得更清楚"。

若原文已通过检测，写明「检测通过」并说明依据（哪几类特征都不存在），不要笼统说"没问题"。
