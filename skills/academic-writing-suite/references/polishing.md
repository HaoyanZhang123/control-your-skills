# 润色、精简与翻译

请求类型为「润色 / 精简 / 翻译」时读本文件。流程骨架在 SKILL.md §7，这里给诊断表与判据。

## 1. 诊断先于改写

**判错失败模式会让所有后续修改白做。**

### 十二类失败模式

| # | 失败模式 |
|---|---|
| 1 | 论文类型逻辑错（methods 论文写成 discovery 叙事，或反之） |
| 2 | 缺口缺失或定位差（读者不知道「这件事为什么还没被解决」） |
| 3 | 有 claim 无证据（断言强度超过可见证据） |
| 4 | 有证据无 claim（列了结果，没说这条结果建立了什么） |
| 5 | 缺少边界或局限（结论读起来比研究设计允许的更宽） |
| 6 | Results 与 Discussion 混在一起（结果段里做跨结果综合或文献比较） |
| 7 | 标题或摘要信号弱 |
| 8 | 术语/缩写/单位/记号跨节不一致 |
| 9 | 证据完整但主文臃肿（把完整证据记录全塞进主文） |
| 10 | 应审稿要求只加不删，段落里出现同功能的重复句 |
| 11 | 同一 claim 或整套统计报告在正文与图注里重复 |
| 12 | 只有句子层面的冗余（结构没问题，纯粹啰嗦） |

### 修复优先级链

```text
论文类型 → 章节任务 → 证据摆放 → 段落必要性 → claim/evidence/边界 → 句子润色
```

一句话原则：**先判断该不该在这儿，再改句子。**

- 不要对「章节任务错了」的稿子做句子润色。先暴露结构问题，再润色。
- 第 9、10、11 类是主文纪律问题：先定「完整读数只在一个权威位置出现」，再动句子。
- 第 8 类是横切检查：术语台账首次接触即建，全程强制规范形式。

**遇到第 1、2、5 类时**：这三类不是句子问题而是论证问题。可以指出、可以给修补方案，但**不得代写作者的论证**。修补需要作者提供未给的信息时写 `[待确认: 具体缺什么]`。

### 判定输出

在修改说明里用一行说明主失败模式，例：`主问题：第 6 类，Results 段内混入 Discussion 综合`。这行是给作者纠错用的，不是审批门。

## 2. 三轴路由

| 轴 | 值 | 判据 |
|---|---|---|
| language | `en` / `zh-to-en` | 素材为中文或中英混排 = zh-to-en；否则 en。**按素材判，不按用户国籍或交流语言判** |
| section | abstract / intro / results / discussion / methods / title | 按请求内容判，可多值 |
| task | polish / compress / translate / sweep | 只改表达 = polish；要压长度 = compress；中译英 = translate；全文一致性 = sweep |

只加载匹配的轴规则，不要读全部。归类后向用户声明一行：`我判为：language=zh-to-en / section=abstract / task=polish，如不对请纠正`。这是进度声明，不是审批门。

**只有 `task=sweep` 才做全文一致性清扫**；局部跟改只复查受影响的术语、数字与依赖它们的结论。

## 3. 反向提纲

把段落按句拆开，每句打功能标签：`主张` / `证据` / `解释` / `限定` / `过渡` / `背景`。

| 看到 | 判定 |
|---|---|
| 一段里两个以上 `主张` 无分隔 | 拆段 |
| `证据` 出现在 `主张` 之前 | 顺序问题，先给主张 |
| 段中 `背景` 不服务当前主张 | 删除或前移 |
| 结尾是 `证据` 而非 `解释/限定` | 读者不知道这段说明了什么 |

只有句子层面的冗余（第 12 类）时，反向提纲会显示每段功能正常——那就只做句级精简，不要动结构。

## 4. 衔接判据

- 相邻句之间必须有可命名的关系：因果、对比、细化、例证、让步。
- 关系真实存在时才用连接词；用 `However` 连接其实不相反的句子是噪音。
- 连续三句以 `Moreover` / `Furthermore` / `In addition` 开头 → 这段在堆清单，不是在论证。
- **主语链检查**：一段的主语在对象之间来回跳（我们 / 方法 / 数据 / 模型）会让读者失去施动者。

## 5. 句长与信息量

- 一句话承担一个功能；用「并且 / 同时 / 以及」连接两个独立主张就拆。
- 名词化过度（`the improvement of`、`the utilization of`）隐藏施动者与动作，优先还原为动词。
- 长修饰链（三个以上前置修饰）拆成从句或改句序。
- 一段的问题用一段的改法解决，不要因为看见全文就顺手重写全文。

## 6. 语体护栏

### 学术语体

- 谨慎、精确优先，不要口语化的自信口吻。
- 不用收缩形式（`don't`、`isn't`）；不用修辞性提问。
- 缩写首次出现即定义，此后只用缩写。
- 目标语体不确定时沿用原文的英语变体（英式 / 美式），**不要混用**。
- 一句一个主要命题；不用逗号连接两个独立分句。
- 避免 `although` / `whereas` 引起的残句。

### 冠词

单数可数名词首次提及用 `a` / `an`，再次提及用 `the`；泛指复数通常不加冠词；唯一实体常用 `the`；抽象名词泛指通常不加冠词。

典型修复：`The hypoxia induces ...` → `Hypoxia induces ...`。

### 数字与单位

- 测量值用阿拉伯数字。
- 数值与单位之间留空格（`25 cm`、`3.2 s`），角度与百分号等约定俗成者除外。
- 范围用连接号并保持全篇一致。
- 统计符号与数学记号保持全篇一致（斜体/正体、上下标）。
- **不得**把数值改成文字写法，也不得在润色中重算或重舍入。

## 7. 过度断言清单

标注并降级：`prove`、`conclusively`、`unprecedented`、`best`、`superior`、`first`。

候选替代：`show`、`suggest`、`to our knowledge`、`among the strongest`、`in this cohort`。

**替代不是机械替换，必须与证据强度匹配。** 把 `prove` 一律替换成 `suggest` 会制造另一个错误：证据真的足够强时，过度对冲同样是失真。

## 8. 表述候选库（功能家族，不是替换表）

先确定这句话在论证里承担什么功能，再选形式；短语必须与证据强度匹配。

| 功能 | 候选形式 |
|---|---|
| 对照 | `in contrast`, `by comparison`, `whereas`, `unlike X` |
| 因果（有证据） | `because`, `led to`, `resulted in` |
| 因果（提示性） | `may contribute to`, `is consistent with`, `could account for` |
| 让步 | `although`, `despite`, `while X does Y, it does not Z` |
| 递进 | `moreover`, `further`, `in addition`（不要连续三句都用） |
| 转折 | `however`, `nevertheless`, `yet`（不要与 `although` 同句叠用） |
| 例证 | `for example`, `such as`, `illustrated by` |
| 收束 | `together, these results`, `in summary`, `overall` |

### 证据动词

| 证据类型 | 候选 |
|---|---|
| 观察 | `we observed`, `was detected`, `exhibited`, `reached` |
| 因果（有干预证据） | `caused`, `drove`, `abolished`, `rescued` |
| 相关 | `was associated with`, `correlated with`, `co-varied with` |
| 能力 | `enabled`, `supported`, `achieved`, `permitted` |
| 比较 | `outperformed`, `exceeded`, `was comparable to`, `did not differ significantly from` |

**禁忌**：用 `caused` / `drove` 描述只有相关性证据的结果。

### 对冲强度

- 弱：`may`, `might`, `could`, `appears to`, `tends to`
- 中：`is consistent with`, `suggests`, `indicates`, `points to`
- 强：`demonstrates`, `establishes`, `shows`（需直接证据）

不要叠：`may potentially suggest`、`could possibly indicate`。

### 局限的写法

- 候选：`is limited to`, `does not establish`, `remains to be tested under`, `the present design cannot distinguish`
- 具体化：把「样本量有限」写成「n=12 只支持检测大于 X 的效应」。
- 不用 `further studies are needed`（无信息量）。

### 展望的写法

结构：命名不确定性 → 能解决它的实验/分析 → 什么结果会改变解释。

候选：`testing whether X holds under Y would distinguish A from B`；`if Z were driven by W, then V would be expected`。

## 9. 中译英的修复模式

**不要逐句翻译。**

1. **先定术语**：模型名、数据集名、指标名、方法名保留原拼写；中文原文里的自造译名一律查证，查不到标 `[待确认: 术语的标准写法]`。
2. **先重排信息顺序，再译句子**：中文常把结论放句尾，英文需要先给主张。
3. **拆长句**：中文一个逗号串起四个分句是常态；英文按「一句一个主要命题」拆。
4. **补显式连接**：中文靠意合，英文靠形合。哪里逻辑关系靠读者脑补，就在英文里写成可命名的连接。
5. **降名词化**：中文的「对……的改进」译成英文时容易变成 `the improvement of`，还原成动词。
6. **保留中文专名**：机构名、基金号、政策文件名，按已发表的英文写法；没有就标 `[待确认]`。

中式英文高频修复：主语缺失、冠词缺失、时态混用、单复数、`the` 滥用、从句套从句、`and` 连接一切。

术语翻译纪律：同一术语全篇只用一个英文对应词；换词会在审稿人眼里变成两个概念。

## 10. 精简（task=compress）

### 主文纪律

每条结果先分类，决定它该在主文、图注、补充材料还是 Methods：

| 内容 | 去处 |
|---|---|
| 理解效应所需的描述量（效应量、区间） | 主文 |
| 支撑主张的主推断量 | 主文 |
| 次要区间、替代估计量、多重比较、敏感性分析、模型级异质性 | 补充材料（除非改变结论或期刊要求正文） |
| 完整数值报告 | 只在一个权威位置出现 |

### 压缩顺序

1. 删背景与教科书知识（目标读者已知的）
2. 删方法细节（移到 Methods 或补充材料）
3. 删次要数字（不通过数字准入测试的）
4. 删次要主张
5. 删不限定主主张的修饰语
6. 合并同功能的重复句

**永不删除防止过强主张的边界句。**

用户给了篇幅预算（如「压到 150 词」）时，先满足预算，再谈风格。

## 11. 一致性清扫（task=sweep）

只有 sweep 才做全文级清扫。产出是一张问题表，不是改稿。

| 位置 | 维度 | 现状 | 期望 | 严重度 |
|---|---|---|---|---|
| 3.2 节 | 术语 | `gut microbiome` / `intestinal microbiota` 混用 | 统一为首次定义形式 | medium |
| 摘要 | 数字 | `n = 48`，正文为 `n = 46` | 核对源数据后统一 | high |

清扫范围：术语、缩写、单位、数值精度、计数、图表指针、引用键、时态、大小写。

**必须写明覆盖边界**：扫了哪些章节、哪些没扫、为什么。没扫的不算通过。

## 12. 排版请求

请求是**排版/版面**（松页、跨页图、Float too large、多面板排布、SI 空页）时，不走三个散文轴，直接按版面问题诊断：定位是浮动体放置、浮动体尺寸、还是文本流断点；给出版面修改方案与渲染前后的实际观察。

期刊硬数字（栏宽、页数、图注词数）必须以目标期刊当前官方说明为准，标核对日期。
