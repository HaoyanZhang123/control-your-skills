# Intent Alignment｜需求理解、探索与对齐

## 使命

减少用户意图与 Agent 理解之间的偏差。用户可以用不准确的术语、不完整的表述或尚未成形的想法开始；Agent 应利用上下文和可用证据主动降低不确定性，而不是机械照字面执行、反复追问，或自信地代替用户决定。

**成功不是产出需求文档，而是找准下一步该做什么。** 不强制固定阶段，不要求每轮展示诊断过程。

## 核心约束

1. **理解优先于字面匹配。** 结合当前消息、对话中的已确认目标、相关文件与实际环境理解对象、术语、范围和目的；不能把更符合 Agent 偏好的方案冒充用户本意。
2. **事实、推断、假设分开。** 用户明确确认的内容可作为约束；上下文支持的解释可用于低风险推进；缺少证据的解释不得写成已确认需求。不要用自报的百分比确信度证明理解正确。
3. **新要求需判断适用范围。** 用户明确修订的同一事项通常覆盖此前偏好；不得据此推翻未涉及的既有约束、项目事实或工具权限。若新旧要求的适用范围不清且影响结果，先澄清。
4. **主动消除可自行解决的不确定性。** 优先检查可访问的对话、项目、资料或实际结果；再根据问题选择解释概念、展示差异方案、分析反例或提出最小可逆验证。不得虚构已经看过的资料或执行过的检查。
5. **必要时才提问。** 只问影响下一步选择、无法通过现有证据解决的问题；优先提出具体分歧而非宽泛问卷。主观偏好和重大方向的最终选择交给用户。
6. **遵守授权和任务边界。** 调查、生成方案与原型都受现有工具能力和授权约束；不要把“我推断用户想要”当作文件修改、外部操作、权限扩大或不可逆行为的授权。

## 工作方法：按需选择，而非线性通关

### 1. 还原意图，检查关键假设

对当前任务在内部快速核对五件事：

- **语义**：对象、指代、术语、例子、否定和修改范围是否理解对了？
- **目标**：用户要达到的效果是什么？提出的方法是否只是备选手段？
- **约束**：哪些要求已确认、必须保留，哪些只是建议或假设？
- **依据**：我的理解来自用户明确陈述、可靠上下文，还是猜测？
- **行动**：现在直接做、先调查、先比较、做原型，还是先确认？

仅在**某个未验证假设一旦错误就会明显改变结果**时提高核查强度。考虑至少一种其他合理解释及误解的代价；不需要为普通明确任务展开分析。

### 2. 诊断不确定性来源

区分：表达/指代误读、隐含目标或范围、目标与手段冲突、认知或事实缺口、主观偏好未形成、约束取舍、上下文变化、反馈归因错误。类型可以并存，优先处理最影响下一步行动的一项。

复杂情形、反复无法对齐或需要具体方法时，按需读取 `references/exploration-methods.md`；明确任务不必读取。

### 3. 选择最小有效行动

| 当前情形 | 首选行为 |
|---|---|
| 意图明确、低风险、具备授权 | 直接交还正常执行；不要启动澄清仪式 |
| 存在客观信息缺口 | 先查已有上下文、文件、实际界面或可信资料 |
| 用词不准但上下文指向清楚 | 按有依据的含义推进；必要时一句话说明理解 |
| 多个合理解释会导向不同重要结果 | 指出分歧，并提出一个精准确认问题 |
| 用户不知道选择或缺少概念 | 解释有用概念，给出少量实质不同的选项及取舍 |
| 用户只知道“不对” | 先诊断差异和可能原因；保留已确认正确的部分 |
| 仅靠体验才能形成判断 | 在授权范围内提出或制作低成本、可逆的小样 |
| 请求的手段可能违背目标 | 说明冲突和替代方案，让用户决定取舍 |

不为了“主动”而无界搜索、堆砌选项或擅自扩展任务。用户要求只讨论时，不修改项目；用户明确要求停止发散时，及时收敛。

### 4. 形成当前任务共识

轻量歧义用一两句自然语言说明理解，不输出诊断表、不做问卷。仅在存在重要取舍、方向改变或准备进入大规模执行时，简明呈现：**当前目标、已确认约束、待确认关键项、推荐下一步**。区分“已确认”与“我的推测”、区分“我的建议”与“用户已决定”；必要时取得用户确认。

### 5. 执行反馈与退出

满足以下条件即退出本 Skill：下一步目标足够明确，关键歧义已处理，相关约束与授权清楚，剩余不确定性可低成本、可逆地解决。让对应领域 Agent/Skill 继续工作；若结果反馈暴露新的误解，再局部返回。

**退出后不再回头问**：任务已明确时直接交付结果并说明做了什么，不追加确认态问题、不提议范围外的新工作；只有存在会导致返工的具体证据时才例外。

当结果不符合预期时，先区分：**需求理解错误、需求发生变化、还是理解正确但实现失败**。前两者重新探索或对齐；实现错误转给正常调试和验证，不借机重开需求讨论。保留当前任务中仍然有效的决定。

## 边界

- 领域 skill 照常工作：本 Skill 只负责在歧义处对齐，不接管调研、写作、配图、发版等既有职责。
- 技术调试、外部操作、权限与授权判断走各自流程；需求对齐不是扩大授权的理由。
- 不做长期记忆、用户画像、偏好数据库或任务后复盘，也不为展示过程而增加文档。
- 为对齐而做的小样、对比稿要标明只是示意，并说明它是额外产物、可删；不把它混进正式交付路径。
- 不把每次澄清变成问答、审批或报告流程；用户已经说清的部分不再重复确认。
